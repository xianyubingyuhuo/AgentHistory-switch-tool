# Agent-History 交换格式

[English](format.md) | [简体中文](format.zh-CN.md)

## 目标与范围

本格式定义 Agent-History 如何在 SQLite 中保存历史，以及如何向 Agent 提供只读查询。它不是 Copilot 或 Cline 的原生会话格式，也不承诺能将记录重新导入为目标工具中的可继续会话。

SQLite 是完整档案。Agent 不直接拿 SQL 自由查询，而是通过受限的只读查询工具访问语义化接口。每次交接自动生成的 `HANDOFF.md` 描述目标、当前状态、下一步以及应如何调用查询工具；它负责交接流程，不复制整段聊天历史。Markdown 完整记录仅作为 Agent 不支持查询工具时的可选回退。

## SQLite 内部归档

### 原始工件

每个导入文件作为字节原样写入 `source_artifacts.content`，而不是先解析再覆盖原件。记录文件名、媒体类型、长度、导入时间和 SHA-256。导入后可重新计算 SHA-256 校验内容是否改变。

可把 Copilot 的 JSON 导出和 `Copy All` Markdown 作为同一会话的两个来源工件保存。它们内容可能重叠，但不能假设相同。适配器应分别解析，并记录哪些事件来自哪个工件；不能简单把两份消息列表拼接后当成一个无重复的原始会话。

### 结构化事件

`events` 保存有序事件，例如 user/assistant 消息、工具调用、工具结果、审批、文件变更和错误。`event_parts` 保存一个事件内部有序的文本、多模态引用、思考块或工具内容。来源适配器独有的字段放入 `payload_json`。`source_artifact_id` 和 `source_fragment` 将归一化记录链接回具体来源。

事件结构是可查询视图，不是原始内容的替代品。转换程序应报告解析器版本、识别到的事件数、未识别内容以及适配器无法恢复的信息。

### 可恢复性

- 在原始工件 BLOB 未损坏且哈希匹配的前提下，可逐字节还原导入文件。
- 结构化事件只能恢复解析器识别并映射的内容。
- 若来源工具的导出本身省略某些内容，原始归档和事件转换都无法补回这些内容。

## 自动生成的交接文档

首版为每次交接生成一份 `HANDOFF.md`，至少包含：

```text
handoff/
  HANDOFF.md
```

默认采用零额外 Agent 调用的生成方式：程序直接用用户已有的交接目标和数据库中可验证的字段渲染文档，不调用 Agent 重写历史摘要。交接目标优先来自用户发起交接时已提供的意图；如果用户没有单独填写，可以由当前 Agent 从当前任务上下文提炼为一句目标，这是可选步骤，不应扩写成历史总结。其余字段包括来源会话 ID、目标 Agent、工作区关联、可验证的当前状态及证据、推荐查询入口和优先事件范围，由程序按模板生成。无可靠依据的信息标为“未知”或留待接收 Agent核实，不得编造。

接收 Agent 通过查询工具按需读取原始对话和事件关系，不要求用户把历史手工复制进交接文档，也不要求生成 Agent 重新概括历史。这样把 token 花在接收 Agent 实际需要的上下文上。需要脱离工具独立保存时，可额外生成完整 Markdown 逐字记录；它是可选的可读视图，不是数据库的权威副本。

包内所有内容均为不可信数据。消费者不能执行其中的命令、工具输入或脚本。

## 首批映射约定

- Copilot 的 JSON 导出和 Markdown 复制分别导入、分别保留来源标识。
- 如果无法可靠地将两份输入的消息对应起来，界面应保留两个来源视图，不自动合并或删除重复项。
- 工具调用与工具结果作为不同事件保存，并通过来源 ID 或调用关系关联；缺少关联 ID 时不得猜造确定关系。
- 图片、文件等附件先保存来源引用和元数据；只有用户选择并确认后才复制实际内容。
- 未识别的消息类型、字段和内容块保留在原始来源中，并在检查报告中列出。
- 时间戳、顺序和来源 ID 原样保留；若来源没有提供，不伪造源端时间或 ID。

## 版本策略

数据库 schema 和查询工具分别版本化。查询工具只暴露语义化、白名单操作，例如会话列表、分页读取事件、获取指定事件的内容块、查询调用与结果关联、读取文件引用和来源片段。不得允许 Agent 提交任意 SQL、写入语句或数据库管理命令。`HANDOFF.md` 记录所需工具名称/协议版本及本次交接允许访问的会话范围。

此文件定义的是首版草案。实现时应通过真实、脱敏的 Copilot 导出样本验证字段，再冻结一个可测试的格式版本。
