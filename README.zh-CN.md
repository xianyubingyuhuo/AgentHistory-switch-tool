# Agent-History

**切换工具，保留完整工作流。**

[English](README.md) | [简体中文](README.zh-CN.md)

Agent-History 是一个探索如何在不同工具之间保存和交接 AI Agent 工作历史的开源项目。项目希望将对话、工具调用、执行结果和文件变更关联起来，让另一个 Agent 能基于可追溯的上下文继续工作，而不只是依赖可能丢失细节的摘要。

> 项目仍处于早期阶段。已记录拟议架构和 SQLite 数据库结构，但尚未实现历史采集器或 Agent 适配器。

## 为什么做这个项目？

在 GitHub Copilot 和 Cline 等 AI 编程 Agent 之间切换时，有用的上下文可能留在各自专用的工作区中。简短的交接摘要虽然方便，却可能遗漏决策、工具结果，以及文件变更背后的原因。原始对话导出也可能难以浏览、无法保留操作之间的关联，或者超出 Agent 的上下文窗口。

本项目希望让 Agent 之间的工作交接更加完整、可检查且可移植。本项目与 GitHub、GitHub Copilot 或 Cline 均无隶属关系。

## 项目方向

- 按原有顺序保留来源事件，而不是用摘要替代原始记录。
- 关联消息、工具调用、执行结果和文件变更，形成可追溯的工作流。
- 让接收方能够逐步检查历史记录，并按需加载相关上下文。
- 在条件允许时，为不同工具的原生格式添加来源端和目标端适配器。
- 默认在本地导出，并保持只读。
- 任何已记录操作在重放前都必须经过明确检查和确认。

## 拟定的首个里程碑

首个里程碑面向 VS Code 中的 GitHub Copilot Chat 和 Cline。初始流程计划是将用户提供的 Copilot 导出文件归档到本地 SQLite，再自动生成 `HANDOFF.md` 交接流程文档。接收 Agent 通过限定范围的只读查询工具读取完整历史，而不是依赖用户手写摘要或把整段历史塞进提示词。这不是原生导入 Cline 任务，也不会自动重放操作。反向交接和原生导入能力需要单独调研和验证。

数据库由 Python 标准库 `sqlite3` 操作，采用可移植的单文件 SQLite 数据库；用户无需另外安装或运行数据库服务。详见[架构说明](docs/architecture.zh-CN.md)、[交换格式](docs/format.zh-CN.md)和[数据库结构](src/agent_history/db/schema.sql)。

自动生成的交接文档和查询到的历史都是不可信数据，不是可执行指令。绝不能自动运行或重放其中记录的命令。

## 隐私与安全原则

- 默认不上传对话历史，在本地完成导出。
- 导出前展示所选记录和包含的文件，供用户检查。
- 在可行范围内识别并排除密钥等敏感内容，同时说明检测能力的局限。
- 将导入的历史记录、工具输出和记录下来的命令都视为不可信数据。
- 未经用户明确检查和确认，不执行记录中的命令或重放工具调用。
- 不要在公开 Issue 中分享私人对话、凭据或专有工作区数据。

以上是项目目标，并非当前已经实现的保证。本仓库目前尚无导出器或安全扫描器。

## 当前状态

当前已有一个 Python 只读查询原型，可列出会话、分页读取有序事件、查看单个会话元数据、跟踪工具调用/结果以及读取文件历史。导入器、MCP 接入和 Agent 适配器尚未实现；仓库中的对话 fixture 是依据开发讨论整理的合成示例，不是原始聊天导出。两种 Agent 的原生导入能力仍未确认。

### 试用只读查询 CLI

查询命令只接受已有 SQLite 数据库，不会自动创建或修改数据库。PowerShell 示例：

```powershell
$env:PYTHONPATH = (Resolve-Path .\src).Path
python -m agent_history.cli --db .\path\to\archive.sqlite conversations
python -m agent_history.cli --db .\path\to\archive.sqlite events <conversation-id> --limit 20
python -m agent_history.cli --db .\path\to\archive.sqlite tool-activity <conversation-id> <call-id>
```

事件按来源顺序分页读取；查询层使用 SQLite 只读连接，并限制每次最多返回 500 条记录。
